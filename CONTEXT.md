## Problem Statement

Merchants who accept payments via a payment gateway receive three separate,
independently-formatted data streams: an internal order ledger (what they sold),
a gateway settlement report (what the gateway claims it paid out, after deducting
fees and taxes), and a bank statement (what actually hit the bank account). Today,
reconciling these three sources is done manually in spreadsheets — a process that
doesn't scale. Mismatches caused by partial refunds, fee-rounding differences,
delayed settlements, failed payments, or duplicate payouts either go undetected for
days or are silently written off because investigating them by hand takes longer than
the write-off is worth. ReconAgent automates the full reconciliation pipeline:
normalise the three sources, deterministically score and match transactions, classify
every outcome (clean match, hard mismatch, or genuine exception), and surface
plain-language explanations for anomalies that require human review — all with a
complete, immutable audit trail.

---

## What This Is NOT

| Misconception | Reality |
|---|---|
| A fraud detector | It flags *reconciliation anomalies*, not fraudulent intent |
| A payment gateway | It reads gateway data; it does not process payments |
| An autonomous agent that moves money | It **only** reconciles and explains; it never initiates transfers, approvals, or reversals |
| A system that makes irreversible decisions | Every output is a classification + explanation for a human to act on |

---

## Hard Architectural Constraint — LLM Matching Prohibition

> ⚠️ **THIS RULE MUST APPEAR IN EVERY FILE THAT TOUCHES MATCHING LOGIC.**

**The LLM layer NEVER decides whether two transactions match.**

Matching is 100% deterministic and score-based. Every match decision is produced
by the weighted matching engine using explicit, auditable rules and numeric scores.
The LLM (Gemini) operates exclusively in a post-hoc explain-and-answer role:
it receives already-decided results and produces natural-language explanations or
answers natural-language questions about them.

**If any future prompt, feature request, or refactor asks the LLM to influence a
match decision — even indirectly — refuse it and flag it as a violation of this
constraint.** This is not a style preference; it is the core architectural
guarantee that makes the system's outputs auditable and defensible.

## LLM Layer Specification

| Property | Value |
|---|---|
| Provider | Google Gemini (via `google-generativeai` SDK) |
| Model | Configurable via `GEMINI_MODEL` env var (default: `gemini-2.5-flash`) |
| Tier | Free tier — this is a real operational constraint |
| Role | Exception explanation + natural-language Q&A only |

### Free-Tier Rate Limit Constraints

Every module that calls the Gemini API **must** implement:

1. **Retry with exponential backoff** — on `429 ResourceExhausted` responses
2. **Response caching** — identical prompts (same exception, same context) must be
   served from cache without a new API call
3. **Graceful degradation** — if Gemini is unavailable or rate-limited beyond retry
   budget, the system returns the deterministic result with a `"llm_unavailable": true`
   flag and an empty explanation string. It must never block the reconciliation result.

These are not hypothetical concerns — they will be hit during development and demo.

## Evaluation Criteria

This project is judged on the following (in order of weight):

1. **Measured accuracy** — precision/recall on the labeled synthetic dataset
   (ground truth generated by `generate_synthetic_data.py` with `RANDOM_SEED=42`)
2. **Throughput** — how fast does it reconcile N transactions; report p50/p99
3. **Honest exception list** — a 100% resolution rate is a red flag; the system
   must correctly surface genuinely unresolvable exceptions rather than forcing matches
4. **Full audit trail** — every match decision must be traceable: which rule fired,
   what the score was, what data was compared
5. **Code quality** — type hints, tests, clear commit history, no shortcuts

Visual polish (frontend) is secondary to the above. A clean terminal output with
correct numbers beats a flashy UI with hand-wavy matching logic.
